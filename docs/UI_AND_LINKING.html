The workspace, and how a claim finds its source

What the Document Analyst dashboard looks like, and the exact chain that turns a click in the register into a highlighted sentence in the contract.

The rail head (orange tile mark, the same icon.svg used as the browser-tab icon) and the top bar share one height, --bar-height. The top bar reads left to right: pile name, document vN, N documents, N disputed (only when non-zero), and the Compliance checks are off notice when the pile has no rulebook.yaml; then, right-aligned, Upload files, Retry analysis when it applies, the final-document.docx download with its version (“No final document yet” before the first commit), and the status pill. The bar wraps on a narrow window rather than clipping; at phone width the rail collapses behind a Piles button. The one-line activity strip at the bottom expands into the full timeline. Clicking the 01_msa.docx → pill under Payment terms highlighted Net 30 on the right — that is the interaction the system exists for: exact provenance.

Step 3 is the one that matters. Offsets index into documents.extracted_text, which is written once and never edited. If we ever patched that string, every stored citation would shift by the length of the edit and quietly point at the wrong words. That single rule is what makes the highlight trustworthy.

The verbatim check happens once, at write time: Gate 1 drops any quote that does not match the text at its offsets. The browser does not re-check the quote. SourcePane cuts the text by offset (api/spans.ts, counting code points), merges overlapping spans, and drops any span that falls outside the text or runs backwards rather than highlighting the wrong words. The quote itself appears only as the pill's tooltip.

A decision is POST /decisions/{id}/approve or …/reject with X-Actor. It writes one row and returns; a table trigger fires NOTIFY, and the worker resumes the paused run on its own sweep once the queue is empty — “the worker commits on its next pass”.

Cost & findings shows four figures — Estimated LLM spend (“unpriced”, never $0, when no rate is configured), Time in models, Failed calls and Open findings — then a Pricing note when /health reports pricing.warnings or some calls have no price (prices never stop a call), a By stage table (Stage · Calls · Tokens in · Tokens out · Time · Cost), and the open findings with their quoted evidence.

Everything on screen is served by our own API from our own database, and the final document from the pile's own folder, so the page stays responsive while a run is paused at the gate. GET …/deliverable/verify (read the .docx back against piles.deliverable_sections) exists in the API but is not drawn in the dashboard.

6 · Renaming a field

Commit knows how to apply a rename; like every change to the document, it goes through review.

StepWhat happens
1A label_change review item proposes Monthly price → Monthly Fee (new label in its payload)
2It is approved in the review queue, like any other change
3Commit re-renders that one section under the new heading — same slot id, so one edit row in deliverable_versions with reason label_change, and every other section's SHA-256 unchanged
4claim_slots.label_override is written in the same transaction as the file and its deliverable_commits row
Step 4 is easy to forget, and skipping it breaks the rename silently. Register content is generated from the taxonomy, so without label_override the next update would re-render the field under its taxonomy name and quietly undo your rename.

No stage and no dashboard control raises a label_change item today; the kind is accepted by the schema and applied by Commit when one is in the queue.

7 · Getting started: setup gate and setup guide

Two components, both reading /health. SetupGate renders instead of the workspace while setup.ready is false: it lists the two requirements (an LLM key and an embedding key) through KeyRequirements, explains how to add them to .env, re-checks every four seconds and has a Check again button. SetupGuide (frontend/src/components/SetupGuide.tsx) is one text in two shapes, and says what to do with this installation because it reads the real values from /health.
