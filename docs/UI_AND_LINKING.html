What the UI looks like, and the exact chain that turns a click in the register into a highlighted sentence in the contract.

3 · How the link actually works

The chain runs from a row in the register to a character range in the extracted text. Four hops, all of them ours:

Step 4 is the one that matters. Offsets index into documents.extracted_text, which is written once and never edited. If we ever patched that string, every stored citation would shift by the length of the edit and quietly point at the wrong words. That single rule is what makes the highlight trustworthy.

Step 5 re-runs the verbatim check client-side. It should never fail — Gate 1 already dropped anything that didn't match at write time — so a failure means a real bug, and it surfaces as a visible message rather than a confident highlight of the wrong sentence.

Everything on screen — register, click, highlight, state, cost — is served from our own database, and the final document from the pile's own folder. Nothing on this page depends on an outside service, so it stays responsive while a run is paused at the gate.

5 · Renaming a field

Renames stay possible; like every change to the document, they go through review.

StepWhat happens
1A label_change review item proposes Monthly price → Monthly Fee
2It is approved in the review queue, like any other change
3Commit re-renders that one section under the new heading — same slot id, so one edit row in deliverable_versions with reason label_change, and every other section's SHA-256 unchanged
4claim_slots.label_override is written in the same transaction as the file and its deliverable_commits row
Step 4 is easy to forget, and skipping it breaks the rename silently. Register content is generated from the taxonomy, so without label_override the next update would re-render the field under its taxonomy name and quietly undo your rename.

Cost: one local file write. What matters is that the register and the document never disagree about what a field is called — and deliverable_commits makes sure the rename is applied exactly once.

6 · Getting started: the setup guide

frontend/src/components/SetupGuide.tsx replaced the old Welcome modal. It is one text in two shapes, and it says what to do with this installation rather than in general, because it reads the real values from /health.

The selected pile and tab live in the URL hash, #pile=<id>&tab=review. The app listens to hashchange, so following such a link — or editing the hash by hand — switches the pile and tab in place, without a reload.
